# vsh — эмулятор командной оболочки UNIX (вариант 26)

Эмулятор языка оболочки ОС с графическим интерфейсом. Работа максимально
похожа на командную строку UNIX-подобной ОС: приглашение
`пользователь@хост:каталог$`, ввод в той же строке, сообщения об ошибках в
стиле bash, коды завершения.

Написан на Python 3 со стандартной библиотекой; GUI — `tkinter`.

## Запуск

```
python3 -m emulator [--vfs PATH] [--script PATH]
```

| Параметр | Описание |
|---|---|
| `--vfs PATH` | путь к физическому расположению VFS; имя файла без расширения — имя VFS в заголовке окна |
| `--script PATH` | путь к стартовому скрипту |

При запуске все параметры выводятся отладочными строками `[debug]` — в окне
эмулятора и в терминале ОС. Несуществующий путь `--vfs`/`--script` (или
каталог вместо скрипта) — сообщение об ошибке в окне, эмулятор продолжает
работу. Неизвестная опция или опция без значения — сообщение `argparse` и
код 2, окно не открывается.

> На macOS с Python из Homebrew tkinter ставится отдельно:
> `brew install python-tk@3.14`.

## Возможности

* **GUI-терминал.** Заголовок окна содержит имя VFS. Уже выведенный текст
  защищён от редактирования, ↑/↓ — история команд, Ctrl+C — отмена строки,
  Ctrl+L — очистка экрана.
* **Парсер** (`emulator/parser.py`, без `shlex`) по правилам sh:
  * `"..."` — двойные кавычки, внутри работают `\"`, `\\`, `\$`, `` \` ``;
  * `'...'` — одинарные кавычки, содержимое берётся буквально;
  * `\` вне кавычек экранирует следующий символ (`My\ Docs`);
  * соседние части склеиваются (`a"b c"'d'` → `ab cd`);
  * `""` даёт пустой аргумент;
  * незакрытая кавычка — синтаксическая ошибка.
* **Команды**
  * `ls`, `cd` — заглушки: выводят своё имя и полученные аргументы
    (каждый аргумент в `[...]`, чтобы были видны границы слов);
  * `exit [N]` — выход из эмулятора с кодом `N` (по умолчанию — код
    последней команды).
* **Комментарии**: `#` в начале слова вне кавычек — остаток строки
  игнорируется (синтаксис Python, совпадает с sh). `"#a"` и `a#b` — обычные
  аргументы.
* **Ошибки** (как в bash): неизвестная команда — код 127, синтаксическая
  ошибка — код 2, `exit abc` — `numeric argument required`,
  `exit 1 2` — `too many arguments` (эмулятор не закрывается).

## Демонстрация (интерактивный режим)

Запустите `python3 -m emulator` и введите:

```
ls
ls -l "My Documents" 'a b' c\ d
cd "/home/user"
cd ""
ls a"b c"'d e'
ls "say \"hi\""
ls "unclosed
pwd
exit 1 2
exit abc
```

Ожидаемый вывод:

```
user@host:~$ ls
ls: аргументы: (нет аргументов)
user@host:~$ ls -l "My Documents" 'a b' c\ d
ls: аргументы: [-l] [My Documents] [a b] [c d]
user@host:~$ cd "/home/user"
cd: аргументы: [/home/user]
user@host:~$ cd ""
cd: аргументы: []
user@host:~$ ls a"b c"'d e'
ls: аргументы: [ab cd e]
user@host:~$ ls "say \"hi\""
ls: аргументы: [say "hi"]
user@host:~$ ls "unclosed
vsh: syntax error: unexpected EOF while looking for matching `"'
user@host:~$ pwd
vsh: pwd: command not found
user@host:~$ exit 1 2
vsh: exit: too many arguments
user@host:~$ exit abc
vsh: exit: abc: numeric argument required
```

После `exit abc` окно закрывается с кодом 2 (`echo $?` в терминале ОС).

## Стартовый скрипт

Текстовый файл с командами эмулятора, по одной в строке; пустые строки
пропускаются. Каждая команда выводится после приглашения, как будто её
набрал пользователь, затем её вывод — получается имитация диалога. Ошибка
не прерывает скрипт (как в sh); `exit` в скрипте закрывает эмулятор. Пока
скрипт выполняется, ввод заблокирован; Ctrl+C прерывает скрипт. После
скрипта эмулятор переходит в интерактивный режим.

Примеры в `scripts/`:

* `demo.vsh` — команды, кавычки, экранирование, комментарии;
* `errors.vsh` — обработка ошибок;
* `exit.vsh` — закрывает эмулятор с кодом 5.

## Скрипты запуска (ОС)

В `os_scripts/` — скрипты `sh`, вызывающие эмулятор со всеми вариантами
параметров (после закрытия окна печатается код завершения):

| Скрипт | Что проверяет |
|---|---|
| `run_no_params.sh` | запуск без параметров |
| `run_vfs.sh` | только `--vfs` (имя VFS в заголовке) |
| `run_script.sh` | только `--script`: `demo.vsh`, `errors.vsh` |
| `run_all_params.sh` | `--vfs` и `--script`, выход из скрипта с кодом 5 |
| `run_bad_params.sh` | несуществующие пути, каталог вместо скрипта, неизвестная опция, опция без значения, `--help` |

Интерпретатор можно задать переменной: `PYTHON=python3.14 ./os_scripts/run_vfs.sh`.
