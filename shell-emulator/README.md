# vsh — эмулятор командной оболочки UNIX (вариант 26)

Эмулятор языка оболочки ОС с графическим интерфейсом. Работа максимально
похожа на командную строку UNIX-подобной ОС: приглашение
`пользователь@хост:каталог$` (домашний каталог — `~`), ввод в той же строке,
сообщения об ошибках и коды завершения как в bash.

Написан на Python 3 со стандартной библиотекой; GUI — `tkinter`.

## Запуск

```
python3 -m emulator [--vfs PATH] [--script PATH]
```

> На macOS с Python из Homebrew tkinter ставится отдельно:
> `brew install python-tk@3.14`.

| Параметр | Описание |
|---|---|
| `--vfs PATH` | путь к JSON-файлу VFS |
| `--script PATH` | путь к стартовому скрипту |

При запуске все параметры выводятся отладочными строками `[debug]` — в окне
эмулятора и в терминале ОС. Неизвестная опция или опция без значения —
сообщение `argparse` и код 2, окно не открывается. Несуществующий стартовый
скрипт (или каталог вместо него) — сообщение об ошибке в окне, эмулятор
продолжает работу в интерактивном режиме.

## Этап 1. REPL

* **GUI-терминал.** Заголовок окна — `vsh — VFS: <имя VFS>`. Уже выведенный
  текст защищён от редактирования; ↑/↓ — история команд; Ctrl+C — отмена
  строки; Ctrl+L — очистка экрана.
* **Парсер** (`emulator/parser.py`, собственный, без `shlex`) по правилам sh:
  * `"..."` — двойные кавычки, внутри работают `\"`, `\\`, `\$`, `` \` ``;
  * `'...'` — одинарные кавычки, содержимое берётся буквально;
  * `\` вне кавычек экранирует следующий символ (`My\ Docs`);
  * соседние части склеиваются (`a"b c"'d'` → `ab cd`);
  * `""` даёт пустой аргумент;
  * `~` и `~/путь` вне кавычек раскрываются в домашний каталог VFS;
  * незакрытая кавычка — синтаксическая ошибка (код 2).
* **Команды.** `ls` и `cd` на этапе 1 были заглушками, выводившими имя и
  аргументы; на этапе 3 они работают с VFS (см. ниже). `exit [N]` — выход с
  кодом `N` (по умолчанию — код последней команды).
* **Ошибки как в bash:** неизвестная команда — `vsh: pwd: command not found`
  (код 127); `exit abc` — `numeric argument required` (выход с кодом 2);
  `exit 1 2` — `too many arguments` (эмулятор не закрывается).

## Этап 2. Конфигурация и стартовый скрипт

Стартовый скрипт — текстовый файл с командами эмулятора, по одной в строке.
**Комментарии** — как в Python: `#` в начале слова вне кавычек, остаток
строки игнорируется (`"#a"` и `a#b` — обычные аргументы). Пустые строки
пропускаются.

Каждая команда выводится после приглашения, как будто её набрал
пользователь, затем — её вывод: получается имитация диалога. Ошибка не
прерывает скрипт (как в sh); `exit` в скрипте закрывает эмулятор. Пока скрипт
выполняется, ввод заблокирован; Ctrl+C прерывает скрипт. После скрипта
эмулятор переходит в интерактивный режим.

## Этап 3. VFS

VFS загружается из JSON-файла **целиком в память**; все операции выполняются
над объектами в памяти, файл не распаковывается и не изменяется (это
проверяет тест `test_source_file_is_not_modified`).

```json
{
  "name": "deep",
  "home": "/home/user",
  "root": {
    "type": "dir",
    "children": {
      "readme.txt": {"type": "file", "content": "текст"},
      "pixel.png":  {"type": "file", "encoding": "base64", "content": "iVBORw0KGgo..."},
      "home": {"type": "dir", "children": {}}
    }
  }
}
```

* `name` — имя VFS для заголовка окна (по умолчанию — имя файла);
* `home` — домашний и стартовый каталог (по умолчанию `/`);
* `root` — корневой каталог; узлы: `dir` (`children`) и `file` (`content`);
* двоичные данные — `"encoding": "base64"`, декодируются при загрузке.

Ошибки загрузки — нет файла, каталог, неверный JSON (со строкой и
столбцом), нет `root`, корень не каталог, неизвестный тип узла, неверный
base64, недопустимое имя, неверный `home` — выводятся в окне с указанием
места; эмулятор продолжает работу с пустой VFS.

### Команды

| Команда | Описание |
|---|---|
| `ls [-a] [-l] [путь...]` | содержимое каталогов; `-a` — скрытые файлы, `.` и `..`; `-l` — подробно (для файлов — размер в байтах после декодирования, для каталогов — число элементов); несколько путей — с заголовками; `--` завершает опции |
| `cd [каталог]` | смена каталога: абсолютные и относительные пути, `.`, `..`, `~`; без аргумента — домой; `cd -` — в предыдущий каталог |
| `exit [N]` | выход из эмулятора |

Ошибки: `ls: cannot access 'x': No such file or directory`,
`ls: invalid option -- 'z'`, `vsh: cd: x: Not a directory`,
`vsh: cd: too many arguments`, `vsh: cd: OLDPWD not set`.

## Примеры

`vfs/` — примеры VFS:

| Файл | Содержимое |
|---|---|
| `minimal.json` | минимальная VFS: пустой корень |
| `files.json` | несколько файлов: текст, пустой, скрытый, двоичные PNG и gzip (base64), каталог с пробелом в имени |
| `deep.json` | 6 уровней вложенности (`/home/user/docs/reports/2024/q1.txt`), домашний каталог `/home/user` |
| `broken_json.json`, `no_root.json`, `root_is_file.json`, `bad_node.json`, `bad_base64.json` | некорректные VFS для проверки ошибок |

`scripts/` — стартовые скрипты эмулятора:

| Скрипт | Что проверяет |
|---|---|
| `demo.vsh` | кавычки, экранирование, комментарии |
| `errors.vsh` | обработка ошибок, продолжение после ошибки |
| `exit.vsh` | выход из скрипта с кодом 5 |
| `vfs_minimal.vsh`, `vfs_files.vsh`, `vfs_deep.vsh` | работа с соответствующей VFS |
| `full_test.vsh` | **все команды этапов 1–3** во всех режимах, включая VFS и ошибки |

`os_scripts/` — скрипты ОС (`sh`), вызывающие эмулятор; после закрытия
окна печатается код завершения:

| Скрипт | Что проверяет |
|---|---|
| `run_no_params.sh` | запуск без параметров |
| `run_vfs.sh` | только `--vfs` |
| `run_script.sh` | только `--script` |
| `run_all_params.sh` | оба параметра, выход из скрипта с кодом 5 |
| `run_bad_params.sh` | неверные параметры командной строки |
| `run_vfs_minimal.sh`, `run_vfs_files.sh`, `run_vfs_deep.sh` | разные варианты VFS |
| `run_vfs_errors.sh` | ошибки загрузки VFS |
| `run_full_test.sh` | полный тест `full_test.vsh` на `deep.json` |

Интерпретатор можно задать переменной: `PYTHON=python3.14 ./os_scripts/run_full_test.sh`.
